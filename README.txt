ANIMEHUB 2.2 — ONE-BUTTON DEVELOPER MODE

Что изменено:
- Режим разработчика вызывается одной кнопкой «⚙ Разработчик» в шапке.
- Если сессия уже есть — Studio открывается сразу, без повторного пароля.
- Если сессии нет — появляется отдельное окно входа.
- После входа открывается рабочая Developer Studio.
- Добавление аниме реально сохраняется сервером в data.json и появляется в каталоге.
- Есть кнопка выхода из режима разработчика.
- Пароль больше не лежит в HTML/клиентском JavaScript.
- Сервер требует ADMIN_PASSWORD и не запускается без него.
- Пароль проверяется через scrypt + timingSafeEqual.
- Сессия HttpOnly, срок 6 часов.
- После истечения сессии доступ автоматически закрывается.
- Есть простая защита от перебора: 5 неудачных попыток -> 10 минут блокировки.
- Каталог получает добавленные разработчиком тайтлы через /api/catalog.

ЗАПУСК В TERMUX

1) Распакуй ZIP и зайди в папку проекта:
   cd ~/animehub_2_2

2) Если Node.js ещё не установлен:
   pkg update
   pkg install nodejs-lts

3) Задай пароль разработчика. Пример:
   export ADMIN_PASSWORD='030881'

   Для настоящего публичного сайта используй свой длинный пароль.

4) Запусти:
   node server.js

5) Открой в браузере:
   http://127.0.0.1:3000

ВАЖНО:
Не открывай public/index.html напрямую, если хочешь рабочий режим разработчика.
Нужен запущенный server.js.

После перезапуска Termux команду export ADMIN_PASSWORD нужно выполнить снова.


ПУБЛИЧНЫЙ ЗАПУСК (RENDER)

1. Создай GitHub-репозиторий и загрузи содержимое этой папки (не ZIP как единственный файл).
2. На Render выбери New -> Web Service и подключи репозиторий.
3. Build Command: npm install
4. Start Command: npm start
5. Environment Variables:
   ADMIN_PASSWORD = ТВОЙ_СЕКРЕТНЫЙ_ПАРОЛЬ
   COOKIE_SECURE = 1
6. Создай Web Service.
7. Render выдаст публичный адрес вида https://имя.onrender.com

ВАЖНО:
- Не загружай ADMIN_PASSWORD в GitHub.
- В этой версии сервер слушает 0.0.0.0, что нужно для Render.
- Бесплатный Render может останавливать сервис после периода бездействия; следующий запрос запускает его снова.
- data.json на бесплатном веб-сервисе не следует считать постоянным хранилищем: для постоянных пользовательских данных позже лучше подключить БД/диск.
